Pipes

CI/CD pipeline monitoring that lives in your browser and goes loud the moment a default branch breaks.

Watches the repos you choose across GitHub Actions and GitLab CI/CD. A badge in your toolbar, a popup for a glance and a side panel to keep open.

Problem

You find out the default branch is broken from a teammate on Slack, not from your own tools. Pipeline dashboards live in tabs you forget to open.

Solution

Pipes watches the repos you choose across GitHub Actions and GitLab CI/CD and surfaces the status in your toolbar. Loud when the default branch fails, quiet when it is green.

Product

A browser extension built on Manifest V3 with Svelte 5 and TypeScript, shipping on Chrome and Firefox. Fully client-side: no server, no tracking, your tokens never leave your browser.

Why I built it

At my current contract we use GitLab and for my own work I use GitHub. I have repositories on both and I wanted a simple way to see what state my pull requests and merge requests are in. I also wanted to see my teammates' work and get alerted when main fails.

How it's built

This didn't need a server. The browser is where I am when I'm making applications, so something on the side that I can easily see felt ideal. No server also means no user tokens to store safely on one: your tokens stay in your browser. I had always wanted to build a browser extension too. I use them a lot so this felt perfect.

Then the stack: Svelte 5, TypeScript, Vite and the crxjs plugin on Manifest V3, with Chrome and Firefox from one codebase.

Built with Claude

Requirements first, a task list with ai-dev-tasks, a design pass in Claude Design, then the build in Claude Code with my own skills. Pipes came first, so this is where that workflow started.

Try it

I use it daily. It's incredibly useful, especially when working with multiple repositories and multiple developers.
